<h1 align="center">Typhon</h1>

<p align="center"><b>Python syntax, compiled to .NET</b></p>

<p align="center">
  <a href="https://typhon-lang.com">Website</a> ·

Typhon is an experimental compiler for type-annotated Python. It reads Python 3.12 source files (extension `.ty`) and
produces ordinary .NET IL. C# code can call what Typhon compiles and derive from its classes, and Typhon code can import
any .NET namespace:

```python
from System.Text import StringBuilder
from dataclasses import dataclass
import math


@dataclass
class Point:
    x: float
    y: float


def path_length(points: list[Point]) -> float:
    total = 0.0
    for a, b in zip(points, points[1:]):
        total += math.hypot(b.x - a.x, b.y - a.y)
    return total


if __name__ == "__main__":
    route = [Point(0, 0), Point(3, 4), Point(6, 8)]
    sb = StringBuilder()
    sb.Append(f"{len(route)} points, ")
    sb.Append(f"length {path_length(route):.1f}")
    print(sb.ToString())
```

`typhon run route.ty` prints `3 points, length 10.0`. `Point` becomes a CLR class with two `double` properties and
`path_length` a static method that takes a `List<Point>`. IronPython also runs Python on .NET, but it keeps Python's
dynamic semantics and runs at about CPython's speed; Typhon requires or infers static types and compiles to the kind of
IL the C# compiler produces. The name is short for **ty**ped **Python**.

## Status

Typhon is a proof of concept: it compiles a subset of Python, and a test harness compares its output with CPython's.
Expect missing features and bugs; the language, the CLI and the generated code can change with any commit. Most of the
code is generated by AI from principles a person defined:

* Typhon source is valid Python syntax, so Python tools work on `.ty` files and CPython can run them for comparison.
* Static types come from annotations or whole-program inference; `dynamic` is an explicit escape hatch.
* The compiler generates C# and lets Roslyn produce the IL, so Typhon and C# share one compilation and one assembly.
* Python's protocols map to their .NET counterparts, so Typhon objects behave like native .NET objects.

## Quick start (.NET 11 SDK)

```powershell
dotnet build Typhon.slnx
dotnet run --project samples/HelloTyphon                  # a .csproj whose sources are *.ty
dotnet run --project samples/MinimalApi                   # an ASP.NET Core minimal API in Typhon
dotnet run --project samples/BlazorApp                    # a Blazor web app: Razor markup, Typhon code-behind
dotnet test samples/XunitTests                            # xUnit tests written in Typhon
dotnet run --project samples/WasmLife                     # Python in the browser on WebAssembly (localhost:5080)
dotnet publish src/Typhon.Cli -c Release -r win-x64 -o tools/typhon
tools/typhon/typhon run samples/scripts/tour.ty           # compile in memory and run, like `python tour.py`
tools/typhon/typhon build samples/scripts/tour.ty --aot -o out/tour-aot   # a native executable
tools/typhon/typhon test tests/pytest                     # pytest-style tests
dotnet test tests/Typhon.Conformance.Tests                # every case must print what CPython prints
```

In a C# project, `.ty` files compile like `.cs` files once the project references the `Typhon` package.
[docs/usage.md](docs/usage.md) has the full commands, the project setup and the benchmark runner.

## How it works

```
 .ty ──► Lexer ──► Parser ──► AST ──► type inference ──► C# + #line ──► Roslyn ──► IL (.dll / native .exe)
```

A source generator compiles `.ty` files inside the same Roslyn compilation as the project's C# code, and `#line`
directives map errors, stack traces and breakpoints back to the `.ty` file. A runtime with Python's builtins and the
commonly used stdlib modules is compiled into every assembly. [docs/architecture.md](docs/architecture.md) covers the
pipeline, the runtime, the CLI and the design decisions.

## Performance

![Speed-up of Typhon over CPython and NumPy](benchmarks/img/speedup.png)

Typed pure-Python programs run 1.9 to 75 times faster than on CPython (geometric mean 11.1x with the JIT, 13.6x as a
Native AOT executable). NumPy programs run at about NumPy's speed, and a Native AOT build is one 1.5 to 1.9 MB
executable that needs about 9 MB of RAM. [docs/benchmarks.md](docs/benchmarks.md) has all tables, including Codon and
Pythran; [benchmarks/REPORT.md](benchmarks/REPORT.md) has the method and analysis.
